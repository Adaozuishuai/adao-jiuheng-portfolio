# 本地博客与写作台

这是可真实保存文章的本地版本。文章保存在 PostgreSQL，图片保存在 `data/uploads`；数据目录和 `.env.local` 均已被 Git 忽略。停止网站或重启电脑不会删除文章。

## 第一次启动

需要 Node.js 22.13+ 和 pnpm。在项目目录打开两个终端。

第一个终端启动独立本地 PostgreSQL，并自动运行迁移：

```bash
pnpm install --frozen-lockfile
pnpm db:local
```

辅助数据库仅监听 `127.0.0.1:55432`，不会连接或改动服务器数据库。首次运行会生成权限为 `0600` 的 `.env.local`。不要提交或分享此文件。

第二个终端启动网站：

```bash
pnpm dev --hostname 127.0.0.1 --port 3000
```

- 网站：<http://localhost:3000>
- 博客列表：<http://localhost:3000/blog>
- 写作台：<http://localhost:3000/admin>

请统一使用 `localhost` 打开网页，使请求来源与 `SITE_URL` 一致。

管理员必须通过本地终端预先设置，没有网页注册或初始化入口。首次使用或忘记密码时运行：

```bash
pnpm admin:setup
```

工具会交互询问账号和密码，密码不回显。只允许一个管理员；重设会撤销所有旧会话，不修改文章或图片。密码不能为空，不限制长度或字符组合，空格按原样保留。

登录后可从“账号安全”修改密码或退出所有设备。修改密码必须填写当前密码，并确认两次新密码一致；修改成功后所有设备都需重新登录。

登录会话有效期为 12 小时。本地按提交账号统计失败次数，15 分钟内失败 5 次后暂停该账号登录至窗口结束；成功登录会清除该账号失败计数，不计入失败额度。应用仅绑定回环地址，不使用客户端转发 IP 头识别来源。

## 写作流程

1. 页脚“管理” → 登录 → “新建文章”。
2. 输入标题和正文；工具栏支持标题、强调、列表、引用、代码块、链接、图片及撤销重做。
3. 正文图片上传后不会弹窗；图片下方可直接填写最多 240 字的可选说明。按 Enter 继续写下一段，按 Escape 返回图片节点。
4. 停止输入 1.5 秒后自动保存最新草稿；顶部会显示保存中、保存时间、失败或版本冲突。`Command/Ctrl + S` 或“存档版本”会额外创建一个永久历史版本。
5. “历史版本”可预览和恢复过去内容。恢复已发布文章会立即更新线上内容，因此系统会先永久保存“恢复前草稿”和“恢复前线上版本”。缺少标题、正文或图片文件的版本不会覆盖线上文章。
6. 标签、摘要、封面和固定链接集中在“发布文章”侧边面板。标签最多 8 个；固定链接仅使用小写英文字母、数字和连字符，留空会自动生成。
7. “预览”会先提交待保存内容。“发布文章”使文章出现在首页和博客列表；编辑已发布文章时，自动保存只更新草稿，必须点“确认更新发布”才会改变公开内容。
8. “下架文章”保留草稿和全部存档并关闭公开访问；“删除文章”采用软删除并需要确认。

图片支持 JPEG、PNG、WebP，每张不超过 10MB。上传后重新编码为 WebP；未被已发布正文或封面引用的图片不会公开。只有自动保存仍在进行或失败时，离开页面才会提醒。链接首次发布后不能更改。

历史版本保存在 PostgreSQL 的 `post_revisions` 表中，不自动清理。自动保存持续更新当前草稿，但自动历史版本每 5 分钟最多生成一个；手动存档、发布和恢复会记录对应事件。存档只保存文章 JSON 和图片 UUID，不重复复制图片文件。历史数量会持续增长，应定期观察数据库体积，不要直接删除仍可能用于恢复的图片文件。

如忘记密码，可在本机终端运行 `pnpm admin:setup`。交互输入不回显密码；重设会同时撤销旧会话。

## 检查与验收

```bash
pnpm exec tsc --noEmit
pnpm build
pnpm lint
```

浏览器端到端测试：先运行 `pnpm build` 并启动本地数据库，然后执行 `pnpm test:e2e:local`（账号安全及博客完整测试）、`pnpm test:e2e:auth`（仅账号安全）或 `pnpm test:e2e:blog`（仅博客）。需要安装 Chrome。测试自动创建独立临时数据库、图片目录和 localhost:3101 测试服务，结束后清理，不修改你的正式管理员或文章。报告分别保存到 `outputs/auth-qa/` 和 `outputs/blog-qa/`。

## 后续部署

本轮只进行本地实现与验收，没有更新公网服务器。后续部署应先核对服务器真实运行目录、数据库、Nginx 和服务配置，再备份、迁移和上线。

生产环境需设置 `DATABASE_URL`、绝对路径 `UPLOAD_DIR`、准确的 `SITE_URL`。使用 `pnpm admin:setup` 在服务器终端设置管理员。HTTP 阶段会话无法加密；启用域名 HTTPS 后更新 `SITE_URL`，系统自动使用 Secure Cookie，旧会话应撤销并重新登录。
